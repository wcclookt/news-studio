# 科技新闻采集与推送系统

**开发者：西新。** 本项目是西新的个人成果，由西新主导开发，AI 辅助。
开发署名说明见 [AUTHORS.md](AUTHORS.md)；界面侧栏及“关于星闻”中也展示此署名。

公开仓库只发布西新主导编写的源码、测试和文档。`config.json`、日志、缓存、虚拟环境以及 NapCat、Steam++ 的本地运行目录均不进入仓库；NapCat 和 Steam++ 请按下方部署说明在目标电脑单独安装。AI 参与开发辅助，不作为项目开发者署名。

定时抓取科技/AI/开源项目/科学/游戏/Steam资讯新闻，用可配置的大模型筛选、评分、双语摘要，推送到 **QQ / 邮件 / Telegram**。

## 功能

- **每日 08:00 日报**：AI 汇总前一天自然日的重要新闻，QQ 按条发送
- **重大新闻实时推送**：评分 >= 8（可配）的重大新闻立即推送
- **双语翻译**：英文新闻自动翻译成中文标题，附英文原文，不丢原意
- **新闻源**（按网站网络要求使用代理或直连）：
  - 科技：IT之家、少数派、爱范儿、CNBeta
  - 游戏：机核网、**Steam 特惠**（目标机靠 Steam++ 加速商店访问）
  - 科学：Nature、Science、ScienceDaily、Phys.org、Space.com、NewScientist、ArsTechnica
  - 开源：GitHub Trending、arXiv AI 论文
- **AI 配置**：18 个服务商预设、自定义 API、本地模型与备用模型；额度与收费以服务商账号为准
- 全链路去重（SQLite），日志轮转

## 桌面配置界面（PySide6）

双击项目根目录的 **`start_ui.bat`** 即可。旧的 `scripts\start_ui.bat` 会转到同一个入口。
启动器检查 Python、依赖版本、Qt 原生界面及系统运行库。缺少 Python 时从官网下载固定版本，校验哈希及签名后安装到项目 `.runtime`，再建立 `.venv` 并安装必需依赖。
缺少 VC++ 系统 DLL 时会下载微软官方安装器并验证签名，Windows 可能要求管理员确认；取消后会保留错误提示，之后可重新启动。
依赖完整时不运行 pip；官方 PyPI 连接失败时尝试一次清华镜像，启动日志在 `logs\bootstrap-ui.log`。
界面仅使用 `PySide6-Essentials`，无需额外安装 WebEngine 等未使用的大组件。
也可以手动安装并启动：

```powershell
python -m pip install -r requirements-ui.txt
python config_ui.py
```

界面采用浅色卡片布局，提供总览、推送渠道、AI 模型、时间与筛选、新闻来源、运行日志、服务与网络和新闻缓存库八个页面。
只用 QQ 时，在“推送渠道”关闭邮箱和 Telegram，它们的账号、授权码和 Token 无需填写。
关闭渠道会单独立即保存，当前任务每次实际发送前也会检查最新开关；开启渠道仍需点击“保存配置”。已停用的渠道不随放弃其他编辑恢复。
邮件重试等待和 SMTP 提交前也会检查开关；已经交给邮件服务器的邮件无法撤回，可能延迟到达。
密钥默认隐藏；NapCat 连接检查只读取登录状态，不会发送测试消息。
“发送 QQ 测试消息”需要选择或输入一个接收 QQ 号，点击一次只发送一条：
“你好，我是星星，这是一条测试连通性的测试信息，你可以忽略此信息。”
该按钮使用当前填写的 NapCat 地址和 Token，无需先保存；超时不会自动重发，请到接收端确认结果。
别人向机器人发送“订阅新闻”后，其 QQ 号会写入配置并在界面内每 2 秒自动同步；退订同样同步，其他未保存编辑会保留。

QQ、邮箱和 Telegram 的接收对象均使用列表管理：点击“添加”填写账号，双击单元格编辑名称或备注，支持 Ctrl/Shift 多选后“删除所选”。手动增删和备注修改后点击“保存配置”，运行中服务从后续发送开始使用新列表。
每个列表都有“刷新”；刷新本机已保存的接收对象会保留未保存的备注。接收账号本身正在编辑时暂不覆盖，发生并发修改时会提示处理冲突。
QQ 列表的“刷新”还会在后台向 NapCat 读取一次好友列表，更新已订阅好友的名称，不会把全部好友加入推送，也不发送消息、不调用 AI；非好友或接口不可用时保留原名称和备注，可手动填写。
QQ 用户私聊机器人发送“订阅”或“订阅新闻”即可加入；发送“取消”“取消订阅”或“退订”即可退出。这些指令直接处理，不消耗模型 Token；订阅时保存消息里的昵称，重复订阅不会覆盖管理员写的备注。
取消订阅会移除接收账号及其显示资料；实际发送每位 QQ/TG 接收人前再次检查已保存列表，已取消用户的后续消息分片会跳过，已经提交给平台的消息无法撤回。
Telegram 支持多个 Chat ID（用户、群组或频道），兼容原来的单个 `chat_id` 配置，编辑保存列表后使用 `chat_ids`。Telegram 私聊接收人需先与机器人开始对话；此处新增的自助订阅指令仅适用于 QQ。
名称与备注保存在本机 `config.json`，恢复全新配置时一并清空，不写入配置备份或公开示例。

其他字段编辑完成点击“保存配置”（或 Ctrl+S）。推送开关保存后立即生效，无需等待当前采集或评分结束。
运行中服务使用独立配置监听线程，通常在保存后约 1 秒内感知完整且有效的新配置，不必等待当前采集结束。
模型地址、密钥、名称和参数从下一次模型请求开始使用新值；推送渠道凭据和接收人从下一次发送使用新值。
QQ HTTP 地址会切换到新设置；WebSocket 端口或 Token 改变时自动断开旧连接并按新设置重连。
已开始的网络请求允许完成，避免中途重试造成重复发送或重复计费。无效/半写入文件不会覆盖上一次有效运行配置。
保存会保留当前配置中的 `_comment_` 中文说明和其他未编辑字段；`config.json.bak` 只保留评分、时间与缓存周期等非私密偏好，不备份密钥、账号、地址或接收人。
配置编辑器与 QQ 自动订阅共用文件锁和原子写入，减少同时保存造成的覆盖或半截 JSON。
如果机器人同时更新了订阅列表，界面会合并未编辑的字段；同一字段发生冲突时会提示重新载入。
打开界面不会自动启动或停止后台服务，也不会自动推送新闻。

底部的“恢复默认…”固定恢复全新空配置：清空模型密钥、模型自定义地址、邮箱账号与授权码、QQ/群号、接收人和 Telegram 凭据，并关闭所有推送渠道。
恢复内容由程序内无账号的默认值生成，不读取历史个人配置或修改过的模板；旧版 `config.json.initial.json` 会被移除，不再创建私密初始快照。
确认恢复后立即写入，需要重新填写账号、模型和接收人后再启用服务。新配置仍会把你随后填写的必要凭据保存在本机 `config.json`，不要把它打包发送给别人。

如需编辑其他配置文件，可使用 `python config_ui.py --config 路径`。

“AI 模型”里的“新闻处理”和“QQ 互动聊天”分别配置自己的主模型和备用模型；两侧设置独立保存。
可以选择 OpenAI、Anthropic Claude、Google Gemini、DeepSeek、通义千问、GLM、Kimi、MiniMax、
xAI、豆包、NVIDIA NIM、硅基流动、OpenRouter、Groq、Ollama、LM Studio、Agnes 或自定义预设，
再点击“应用预设”填写协议、地址和模型示例；API Key 保持原值。模型示例不是账号权限保证，
请使用服务商实际支持的模型 ID，地址、模型名和调用协议都可继续编辑。
支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages 三种协议。
Ollama / LM Studio 等本地服务可以取消“需要 API Key”；备用模型不使用时清空 Key 并保持需要 Key 即可。
应用云服务预设时输出上限至少设为 8192 Token，避免推理模型只返回思考内容；可在高级设置调整。

“服务与网络”提供“运行全部服务”“停止全部服务”，管理本项目新闻后台、NapCat 与 Steam++。
也可勾选“新闻与 QQ 互动后台”“NapCat”“Steam++”中的一项或多项，点击“启动所选”“停止所选”“重启所选”。未勾选的服务保持原运行状态。
同页的“QQ 扫码登录”展示区从 NapCat 本机生成的 `napcat/cache/qrcode.png` 读取图片，每 2 秒检查最新版本，无需第三方二维码网站，也不会复制到新闻缓存或配置文件。
未启动或进程已退出时显示“暂未启动 NAPCAT 服务”；启动后先等待本次进程生成二维码，图片更新后自动替换，确认 QQ 已登录则隐藏图片并显示登录状态。
旧会话图片、超过 2 分钟的旧码和不完整图片不会显示；“重新读取二维码”用于重新检查本地文件，不会自动登录或操作手机确认。
停止本项目 NapCat 后会清理其旧二维码文件。使用自定义 `NAPCAT_WORKDIR` 时，界面需在相同环境下启动；外部工作目录只读取，不主动删除。
二维码属于临时登录信息，请勿截图外传；窄窗口下展示区会自动移到服务控制台下方。
重启先停止所选服务并确认退出，再按 Steam++ → NapCat → 新闻后台的顺序启动；未能停止的服务不会再启动第二份。
应用路径改变用于下一次启动；NapCat 自身端口、鉴权与 Steam++ 加速规则仍由对应应用管理，需要与新闻助手配置一致。
仅升级代码时需重启一次新闻后台加载新版；之后普通设置修改无需反复重启。
启动优先使用匹配当前项目和配置的 Windows 服务，没有对应服务时启动独立后台进程；不会重复启动已识别进程。
停止按完整程序路径、项目入口和配置路径识别进程，配置窗口和其他 Python 程序不会被当作后台关闭。
NapCat 初次运行仍可能需要扫码登录，Steam++ 初次运行需要自行配置 GitHub / Steam 加速。
Steam++ 路径可在该页选择；自动状态每 8 秒刷新，显示后台、NapCat、Steam++、QQ HTTP 登录及 WS TCP 端口状态。
“检查网站连通性”单独测试 GitHub Trending 和 Steam 新闻采集接口，显示 HTTP 结果及耗时。
Steam++ 进程运行、QQ 已登录和网站可访问是独立状态。
GitHub / Steam 的检测和采集共用线路选择：配置代理连接失败后，尝试环境代理、Windows 静态系统代理和直连（包括系统 VPN / Steam++ DNS 加速）。
检测显示真实成功线路、HTTP 结果、失效代理原因与总耗时；耗时包含线路切换，不能把约 2000 ms 本身当作加速器失效。
采集会短暂缓存成功线路，减少反复等待失效端口；网站返回 401/403/429 等 HTTP 拒绝时不会轮换线路绕过限制。
浏览器 PAC 自动代理不能直接在 Python 中执行，需填写有效 HTTP/SOCKS 代理或使用系统 VPN。其他采集源仍按各自代理设置工作。
原有 `scripts\start_all.bat`、`stop_all.bat`、`start_service.bat` 和 `stop_service.bat` 也使用同一套进程识别逻辑。

新闻评分仅对缺失结果做一次定向修复，不再在 API 失败后重复整批请求；已评分结果全部入库，避免达到推送上限后的剩余新闻下轮重复评分。
仅 QQ 的日报复用已有评分与解读，省去没有使用的模型速览。评分输入去除 HTML、重复标题和段落，保留来源与事实；同一平台的不同事件不会仅因共享名称被删除。
QQ 聊天保留每位用户最近两轮、15 分钟的上下文，支持“清空对话”；帮助、订阅和退订不调用模型。
链接解读会提取公开页面的正文节点、结构化正文和央视 `contentdate` 内嵌正文，不执行网页脚本。
支持 HTTP 短链接跳转和常见 QQ JSON 分享卡片，采用配置代理、系统代理和直连的网络回退逻辑。
每条链接默认最多向模型提供 6000 字符（原先 1200）；超出会标记截断，简介/标题/读取失败也会明确标记，不能声称已读全文。
只取得部分内容或读取失败的短缓存为 30 秒，正常提取为 5 分钟；下载有大小、跳转次数和读取时限，不自动执行登录、验证码、付费墙或任意 JavaScript。
需要浏览器实际运行脚本、登录/验证、PDF/图片/视频等页面仍可能无法提取文字；可粘贴原文继续解读。网页内容和来源可信度不等同于独立事实核验。
模型调用日志只记录 API 实际上报的输入、输出、缓存 Token；未上报的用量不估算。节省比例取决于新闻和聊天内容。

已评分与已推送分别记录。最近 24 小时内达标但发送失败的新闻会保留待发，即使下一轮没有新新闻也会补发；已成功渠道不重复发送，补发不调用模型。
补发保留现有阈值与可信度过滤，不会为了测试而推送全部历史条目。摘要、来源及解读会保存供重试使用。
日报到达配置时间后执行，错过轮询窗口会在当天后续检查补执行；成功记录写入数据库，后台重启不会重复发送当天已完成的日报。
QQ 日报先单独发送“接下来是昨天的新闻总结”，接着逐条发送新闻，全部成功后单独发送“昨天的总结到此结束”；暂无达标新闻时会在两句之间说明。发送中途失败不会误报总结已结束。
配置监听独立于采集任务运行；配置变更会唤醒调度检查并重新计算采集间隔，日报/待发在当前任务结束后或空闲检查中执行。
待发约每分钟检查，空闲时最多等待 30 秒检查日报；已开始的采集或模型请求不会被强行终止。

## 隐私检查与恢复

`python scripts/privacy_audit.py` 只在本机检查项目，报告文件路径、类别和匹配数量，不打印私密原值，也不上传内容。
`python scripts/privacy_audit.py --clean` 用于将项目恢复到可重新配置的空状态：执行前必须关闭项目界面、新闻后台、NapCat 和 Steam++。
清理会重置当前配置和示例模板、移除旧私密备份、项目日志、旧数据库备份、项目内 NapCat/Steam++ 用户配置、登录缓存与本地证书副本，随后需要重新配置这些应用。
公开新闻缓存保留，检测到的私密文本会被清理，SQLite 重建以移除空闲页中的旧内容。不创建包含私密原文的恢复包。
自动配置备份仅包含允许的非私密偏好；日志会掩码已登记密钥、邮箱、标识号和链接令牌参数，聊天不再把消息正文和回复正文写入日志。
`.gitignore` 排除本机配置、日志、数据和应用用户状态；它不能替代对已有压缩包、历史上传或其他电脑副本的清理，也不会撤销已发出的 API Key。

## 新闻缓存库

沿用 `data/news.db` 保存采集新闻和 AI 评分，不复制一套缓存，也不设置条数上限；容量由可用磁盘空间决定。
每轮采集先对比全部保留新闻：去除 URL 追踪参数后比对链接、比对原始标题、保守判断近似标题，并比对长简介的内容指纹。
重复新闻不再次调用模型、不新增新闻记录，也不再次推送；未发送成功的原记录仍按待发逻辑处理。
标题判断保留型号、版本与数字差异，避免同一平台的不同事件被误删。不同措辞的同一事件不保证全部识别，去重检查本身不调用付费模型。
评分后入库还会在数据库事务内再次比对，减少并发采集产生的重复记录。保留原始简介、来源、摘要与解读供界面查看。

“新闻缓存库”页面支持搜索、单选、Ctrl/Shift 多选、全选当前页、全选全部搜索结果、取消选择、刷新、删除所选和清空全部。
列表每页显示 100 条，这只是界面分页，数据库存储数量不受分页限制。选中新闻可查看完整链接、摘要和原始简介。
跨页全选按选择时的结果删除，不会顺带删除后来新采集的新闻；删除前有确认，其他窗口已清理过缓存时要求刷新。

默认开启每 **7 天于本机 03:00 清空全部缓存新闻**，周期和执行时间可编辑，也可关闭自动清理。
首次启用新版缓存时开始计时；手动清空全部会重新开始周期。清理配置保存在 `cache.auto_clear`、`cache.interval_days` 和 `cache.clear_time`。
后台服务约每 30 秒、配置窗口约每分钟检查到期情况；两者均关闭时不会后台唤醒电脑，下次打开后会补执行一次。
自动清理使用已经保存的设置，修改后点击“保存清理设置”或底部“保存配置”。

清空移除全部缓存新闻及对应待发/投递记录，保留账号配置和日报完成记录。清除后去重记忆也随之消失，同一条新闻仍在新闻源中时可能重新入库和推送。
清理期间已在 AI 处理中的旧批次会被取消入库，避免刚清空又写回；已提交给 QQ/邮件服务器的消息无法撤回。

## 推送格式

## 部署到目标机器（嵌入式机 / 任何 Win10 x64）

> 目标机建议：i3 2310M / 4GB RAM / Win10。本项目为轻量 Python 脚本，内存占用约 50-100MB，CPU 占用低，嵌入式机完全可跑。NapCat 是最大内存消耗者（0.5-1.5GB），4GB 机器上请勿同时开浏览器等大程序。
>
> **网络前提**：目标机只需能上国内网。**Steam++（Watt Toolkit）用于加速 GitHub / Steam 商店**（开「网络加速」勾选 GitHub、Steam 即可，免费）。无需任何代理软件。

### 1. 环境准备

- 安装 **Python 3.11 x64**（安装时勾选 "Add python.exe to PATH"；低配机建议关闭"安装后立即运行"和文档）
- 项目自带 `scripts\nssm.exe`，无需另装 nssm

### 2. 拷贝项目 + 装依赖

把整个 `MYSTRICPROJECT` 文件夹拷到目标机（例如 `D:\MYSTRICPROJECT`），然后：

```powershell
python -m pip install -r requirements.txt
```

### 3. 配置 config.json（目标机上改）

- `push.qq.http_base`：NapCat 的 HTTP 地址（默认 3000 端口）
- `push.qq.private_qq`：接收新闻的 QQ 号列表，默认留空；可由 QQ 用户发送“订阅新闻”自助加入
- `push.email`：填写你自己的 SMTP 发件账号和收件人
- `llm.primary`：填写你自己的模型 API Key 和地址
- **不需要**改 `proxy`（留空 = 全部直连）

### 4. Steam++（加速 GitHub / Steam）

1. 安装 Steam++（Watt Toolkit），打开「网络加速」
2. 勾选 **GitHub** 和 **Steam**，点启动加速
3. 之后 GitHub Trending、Steam 特惠就能访问了（不加速时这些源抓取失败自动跳过，不影响其它源）

### 5. NapCat（QQ 机器人）

1. 下载 **NapCat.Shell.Windows.Node**（无头版，已内置 QQ+Napcat）
2. 运行 `NapCat.Shell.Windows.Node\napcat.bat`（管理员），控制台/图片显示二维码，用**QQ 小号**手机扫码登录
3. 登录后自动开启 **HTTP 服务**（`127.0.0.1:3000`，用于推送）和 **WebSocket 服务**（`127.0.0.1:3001`，用于接收消息+AI交互）
4. 有鉴权 token 就填到 config.json 的 `push.qq.access_token`
5. `push.qq.private_qq` 默认为空；向机器人发送“订阅新闻”加入推送，发送“取消订阅”退出，也可以用 `scripts\manage_qq.bat` 管理；机器人会回复收到的任意 QQ 用户，不绑定固定 QQ 账号

> ⚠️ **账号专属配置（重要）**：NapCat 会优先读取 `napcat/config/onebot11_{QQ号}.json`（QQ号为登录小号的数字）。若目标机登录的 QQ 号与配置文件里的号不一致，OneBot 的 HTTP/WS 服务不会生效。处理方法：
> - 登录后用手机看机器人QQ号（或在 WebUI 看），然后复制 `onebot11.json` 改名为 `onebot11_{你的QQ号}.json`，重启 NapCat；**或**
> - 删除所有 `onebot11_*.json` 账号专属文件，只保留通用 `onebot11.json`（已含 HTTP 3000 + WS 3001 配置），NapCat 会读取通用配置。
>
> ⚠️ QQ 小号风控提示：用养过一段时间的号，别用新号。推送频率已受控。

> 💡 **首次部署三步**（目标机）：
> 1. `NapCat.Shell.Windows.Node\napcat.bat` 扫码登录
> 2. 管理员运行 `scripts\install_service.bat`（装 news-agent 服务，**自动带上 QQ 交互机器人**）
> 3. 管理员运行 `scripts\setup_autostart.bat`（开机自启）

### 6. Telegram（可选，仅限有代理的电脑）

> 目标机只有 Steam++、无代理，**无法访问 Telegram**，此渠道默认关闭。若将来用有代理的电脑运行，可把 `push.enabled` 加上 `"telegram"`，并在 `push.telegram.proxy` 填代理地址。

### 7. 注册为 Windows 服务（nssm，开机自启）

项目自带 `scripts\nssm.exe`，无需安装。

管理员终端（右键「以管理员身份运行 cmd」）执行：

```powershell

```

脚本会自动：找到 Python → 注册 `news-agent` 服务（开机自启）→ 立即启动。日志写 `logs/`。

```powershell

scripts\nssm.exe restart news-agent
scripts\nssm.exe stop news-agent
```

卸载：`scripts\uninstall_service.bat`

### 8. 开机自启确认

- Steam++：设置里开「开机自启 + 自动加速」
- NapCat：设为开机自启（或注册成服务）
- news-agent：nssm 默认 AUTO_START

三条链路都自启后，断电重启无需人工干预。

## 常见问题

- **Steam 特惠抓不到 / GitHub 抓不到**：说明 Steam++ 没开加速或没勾选对应项，开启即可；抓取失败会自动跳过，不影响其它源
- **Agnes API 报 429（限速）**：免费档 20 RPM，系统已加限速（3 并发 + 请求间隔），超限自动降级智谱，不影响接收
- **Agnes API 返回空/解析失败**：偶发，自动重试一次，再失败走兜底分类，之后降级智谱
- **QQ 推送失败**：确认 NapCat 在跑、HTTP 服务开启、端口一致、小号在线
- **日报**：每天 08:00 总结前一天自然日新闻；QQ 按新闻逐条发送，邮件保留完整日报
- **邮件 554 DT:SPM**：163 临时风控（短时间多封含链接邮件触发），等几分钟自动恢复；生产每天几封不会触发
- **日志乱码**：日志文件是 UTF-8，用记事本/VSCode 打开正常；PowerShell 终端乱码不影响
